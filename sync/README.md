# Синхронизация учебных репозиториев

Работа обновляет локальную копию `rurewa/imfua` и переносит материалы в отдельный репозиторий `my-mfua-notes`. Автор учебных материалов — `rurewa`. В корне сохранены оригинальный `README.md` и структура курса, поэтому ссылки на `/content` работают в GitHub. Этот отчёт и скрипты находятся в `sync/`. [Репозиторий преподавателя](https://github.com/rurewa/imfua) · [Методичка](https://github.com/rurewa/imfua/blob/main/content/StudentPracticalsLabs/scriptSyncRep.md)

## Запуск

Откройте Git Bash или PowerShell в Windows. Нужны Git и `tar`. Клонируйте репозиторий с работой и перейдите в него.

```text
git clone https://github.com/aleks-maker-maker/my-mfua-notes.git
cd my-mfua-notes
```

**Git Bash**

```bash
bash sync/sync.sh
```

**PowerShell**

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\sync\sync.ps1
```

Параметр `-ExecutionPolicy Bypass` действует только в этом процессе PowerShell. Оба скрипта при первом запуске выполняют `git clone` в соседнюю папку `imfua-sync-source`. Другой путь к отдельной копии можно передать первым аргументом Bash или параметром `-SourcePath` в PowerShell.

## Что делает скрипт

1. Проверяет, что источник и приёмник находятся в разных репозиториях и их каталоги не вложены друг в друга.
2. Проверяет `origin`, ветку `main` и состояние файлов источника. Выполняет `git pull --ff-only origin main`.
3. Создаёт временный архив командой `git archive HEAD` и распаковывает его в приёмник. Так переносятся файлы из коммита преподавателя, а каталог `.git` остаётся в исходном репозитории.
4. Заменяет одноимённые файлы и печатает хеш исходного коммита. Каталог `sync/` отведён под скрипты и отчёт. Файлы, исчезнувшие из исходного репозитория, при копировании остаются в приёмнике.

После синхронизации `git status --short` показывает изменения для просмотра перед отдельным коммитом. Скрипты выполняют обновление и копирование. Публикация делается вручную.
